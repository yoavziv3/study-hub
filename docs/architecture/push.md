# Phone notifications (cloud only)

Web Push is implemented with plain WebCrypto in `cloud/lib/webpush.js` (VAPID + aes128gcm); `cloud/lib/notify.js` decides what is due (deadlines, exam tomorrow, due flashcards, class in 15 minutes, room change of the student's group) and dedupes via the `push_sent` table. Pages Functions have no cron, so a separate Cloudflare Worker (`workers/push-cron`, deployed with `npm run deploy:cron`, secret `ADMIN_SECRET`) POSTs `/api/admin/push/tick` every 5 minutes. The Mac's `server/lib/push-tick.js` ticks too as a backup (`{ backup: true }`); the cloud skips those while the Worker has ticked in the last 8 minutes (`push_meta` table), so the two never race. Keys: `VAPID_PUBLIC_KEY` in `wrangler.toml`, `VAPID_PRIVATE_KEY` as a Pages secret (generate with `node scripts/vapid-keys.js`). Students' per-kind preferences live in their progress blob (`progress.notify`). News about the courses (new material, announcements, class changes, portal notices, the weekly report) is pushed at any hour; only reminders (deadlines, a lapsed Moodle sign-in) wait for 08:00–22:00. The owner (the degree committee) also hears at once about every connected student's portal notices – each notice once, with no student named – both as pushes (`otherPortal` in `dueNotifications`, not held for Claude's reading) and in their updates feed (`portalFeed` with `owner`); their own portal link is read every 5 minutes, the others' every 15 (`STALE*` in `portal.js`), and Moodle courses are looked at every ~4 minutes. The portal connect form tells students that such notices may show to the site's owner. The owner follows only the cohort's groups – the registration lines the faculty offered (`lines` in `data/committee.json`, turned into `{ course: { type: [groups] } }` by `cohortGroups` in `shared/groups.js`; `forOtherGroups` takes lists of groups): announcements, class changes and other students' portal notices (`lessonInCohort`) about other groups are neither pushed nor shown on the updates page (a toggle shows them), and the owner gets announcements and class changes of the cohort's groups of every course (`owner` in `dueNotifications`; the updates page doesn't hide other groups from them either), students only their own group's.

The tick also watches Moodle without the Mac (`cloud/lib/moodle-watch.js`): a few courses per tick, each about every 10 minutes, through the token of an enrolled student (`asCourseMember`). It lists new files (classified by `shared/moodle-kind.js`, shared with the Mac's ingest) and news-forum posts into `cloud_updates`; the first look at a course only records a baseline in `moodle_watch`. `mergeUpdates` folds these into the feed (`gate.js`) and notifications, dropping any the Mac already has by `key` (`announcement:<discussion>`) or `fileKey` (`<moodleId>:<cmid>:<path><name>`, stored in the lecture's `source.fileKey`). Cloud file notices wait 30 minutes so a running Mac can get there first; when the Mac's item for an already-announced file arrives, it is sent as "מוכן באתר". A student whose Moodle token expired (`token_ok = 0`) gets a weekly "reconnect" notification and a banner on the site.
