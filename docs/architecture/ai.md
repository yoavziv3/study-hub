# AI (`server/lib/ai.js`)

`generateJSON` (structured output against a JSON schema) and `chatStream` (SSE to the client via `/api/chat`). Provider is `api` (Anthropic SDK, needs `ANTHROPIC_API_KEY`), `cli` (spawns the local `claude` binary headless with no tools/settings, using the owner's login) — `cli` is the default when no key is set — or `gemini` (`AI_PROVIDER=gemini` + `GEMINI_API_KEY`, `server/lib/gemini.js`, SDK `@google/genai`). With Gemini the lecture and notes calls also attach the deck's PDF (`deckPdf` in ingest.js; inline up to 18 MB, File API above, 50 MB max), Gemini reads its pages as images, and the prompts add `DECK_PDF_RULES` (extract every number, definition and example) and `DECK_PDF_QUIZ` (40–80 questions in the same call). Free-tier limits are enforced locally: one call at a time spaced to `GEMINI_RPM`, a per-Pacific-day count against `GEMINI_RPD` (default 20 – Google's free-tier limit per project per model for flash; a "per day" 429 from Google marks the day used up) (`logs/gemini-usage.json`), low-priority calls (question banks) stop at `1 - GEMINI_RESERVE` of it, and a used-up day or Google's 429 surfaces as a usage-limit error that the AI watch waits out. Every `generateJSON` answer is cached by its full request – provider, model, system, prompt, schema and the sha256 of attached files (`server/lib/ai-cache.js`, `cache/ai/`, gitignored) – so the same deck is never sent twice; `cache: false` (regenerate) skips it. **`CLAUDE_UNTIL` (set to 2026-12-04 on the owner's Mac, Max plan):** until that Israel date (inclusive) Claude writes every lesson – also courses set to Gemini (`aiBy`) – with Gemini as fallback (`claudeBoost` in `ai.js`), and the question banks at any hour, up to `BANK_CLAUDE_BOOST_CAP` (60) rounds a day (`practice.js`). After it the settings below apply again by themselves. **Current setting on the owner's Mac (to save his weekly Claude quota): `AI_LESSONS` is off – lessons are written by Gemini alone, no Claude fallback – and `BANK_CLAUDE_CAP=10` rounds a night.** What follows describes the `AI_LESSONS=claude` mode. **Lessons vs everything else:** `AI_LESSONS=claude` (with `AI_PROVIDER=gemini`) sends the lesson material – the lecture/tutorial/homework analysis (summary, topics, glossary, flashcards, the lesson's first questions) and the structured notes – to Claude (`AI_LESSON_MODEL`, default Sonnet, 12-minute call limit) and falls back to Gemini when Claude fails (timeout, usage limit, signed out, an output the checks reject): `generateLesson({ build(by), check })` in `ai.js`, `lessonRoute()` / `lessonsReady()` say who is tried. Gemini gets the deck PDF and the bigger first question set (`DECK_PDF_*`), Claude the text. Question banks, extra practice, syllabus, weekly report and chat stay on `AI_PROVIDER` (Gemini), so the free-tier quota (`GEMINI_RPD`, 20 a day for flash) goes to the banks (`GEMINI_RESERVE` keeps a few for the fallback). `checkAI` also probes Claude (`probeClaude`, `aiWatch.claude`) and retries failed lessons when either answers. The saved `content.generator` says who wrote it. All prompts and schemas live in `server/lib/prompts.js`. AI is unavailable in the cloud build.

A dropped internet connection on the Mac (every call "fetch failed") is treated as a blip, not an outage: the AI watch looks again after 3 minutes and alerts only after three misses (`isNetworkError`, `checkAI`), and a Moodle sync whose errors are all network errors is retried after 3 minutes and shows as a problem only when the next one fails the same way (`state.netFails`).
