# System status (owner only)

`/system` shows whether each moving part ran lately: the cron Worker, the Moodle watcher (per-course errors in the `health` table, `watch:<moodleId>`), the portal readers (`portal_relay:<source>` in `push_meta`), the Mac and its publishing, new files waiting for a summary, and students' connections. The checks are built in `cloud/lib/health.js`; the Mac's part comes from a heartbeat (`server/lib/health.js` `macHealth`) sent with every Mac tick and stored as `health` row `mac`, and its checks are in `shared/system-checks.js` (also used locally when the cloud doesn't answer). The owner is the Moodle user the Mac is signed in as (sent in the heartbeat, `push_meta` key `owner`); only that user gets `owner: true` from `/api/me` and can read `/api/system`. The owner also sees every site course in the cloud – feed, new-material/announcement notifications and the material itself (`visibleCourseIds` in `cloud/lib/account.js`, used by `gate.js` and `notify.js` as `feedCourses`); courses they aren't enrolled in come back from `/data/courses.json` with `other: true` and are listed under "קורסים של סטודנטים אחרים". Everyone else sees only their enrolled courses (`allowedCourseIds`). On the Mac, `/api/system` posts a fresh heartbeat to `/api/admin/system` and returns the cloud's answer. Two checks guard against quiet failures: **Claude on the Mac** – `checkAI` (`server/lib/health.js`) runs `probeAI` (a tiny request on the smallest model) every 30 minutes, reports `aiWatch` in the heartbeat (signed out / limit / error → alert), and when Claude answers it calls `retryFailedAI({ auto: true })` (`ingest.js`: items with `aiError`/`notesError`, at most `AUTO_RETRIES` per item via `meta.aiRetries`, reset on success; the manual `POST /api/maintenance/retry-ai` has no cap); and **the cloud deploy** – the heartbeat carries the Mac's `origin/main` commit (`git`), and `cloud/lib/health.js` compares it with the live `data/build.json`, alerting when the site is still on an older build 30 minutes later (a failed Cloudflare build leaves the old site up without telling anyone). Each tick turns a check's `alerts` into phone notifications to the owner (08:00–23:00, keyed `health:<key>:<date>` so at most once a day each, or once ever with `once`). For local cloud testing, the `mock-moodle` and `cloud-dev` (`wrangler pages dev`) launch configs work together (`.dev.vars` points `MOODLE_URL` at the mock).
