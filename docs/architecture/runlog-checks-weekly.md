# Run log, AI output checks, weekly report

- **Run log** (`server/lib/runlog.js`): every process run is one JSON line in `logs/runs.jsonl` (`STUDY_RUNLOG` overrides) – process, trigger, start/end, input, output, status (`ok` / `checked` / `rejected` / `error`) and the checks' findings. `startRun(process, { trigger, input })` → `.ok(output, checks)` or `.fail(error, checks)`. Logged: lecture analysis, notes, syllabus grading, practice, homework practice, notices, Moodle sync, publish, weekly report. The local `/runs` page lists them and exports CSV (the project's documented-runs appendix). runlog.js must not import store.js (store → publish → runlog cycle).
- **Fixed checks after every AI step** (`server/lib/checks.js`): `checkLecture`, `checkNotes`, `checkQuiz`, `checkProblems`, `checkGrading`, `checkNotice` clean what a rule can fix (findings `fixed`/`warn`) and `assertUsable` throws `CheckError` on a `reject` (the output isn't saved; the item gets an `aiError`). Anything new that saves model output should go through one of them.
- **Weekly load report** (`server/lib/weekly.js`): Sunday from 07:00 (checked hourly) or `POST /api/weekly/run`; covers the 7 days from the day it's made. Dates, counts and load points are deterministic (`shared/weekly-load.js`); the AI writes only a headline and per-course advice, checked by `checkWeeklyText` (no course names or digits in the headline, known courses and dates only) with fixed fallbacks. Saved to `data/weekly/<date>.json` (published), announced as a `report` feed item (cloud push rule 8). In the cloud `/data/weekly.json` is filtered per student by `forCourses` in `cloud/gate.js`. Personal state (submitted or not) must stay out of it – the report is shared.
- **`docs/runbook.md`**: the Hebrew operating instructions for someone who didn't build it (mock Moodle, `STUDY_DATA_DIR`, no cloud), kept in step with these processes.
