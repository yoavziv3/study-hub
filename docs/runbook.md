# הוראות הפעלה – מחברת (Study Hub)

המסמך מיועד למי שלא בנה את המערכת ורוצה להריץ אותה בעצמו (מבחן ההעברה): להתקין, להפעיל את הצינור מקצה לקצה על מודל מדומה, להריץ כל תהליך בנפרד, ולבדוק בעצמו שהפלט תקין. אין צורך בחשבון באוניברסיטת בן־גוריון.

זמן משוער: כ־20 דקות להתקנה ולהרצה הראשונה, ועוד כמה דקות עד שה AI מסיים לעבד כל קובץ.

---

## 1. מה המערכת עושה

מחברת היא אתר לימוד לסמסטר. קובץ שמרצה מעלה למודל (מצגת או PDF) נקלט אוטומטית, עובר המרה וחילוץ טקסט, ומודל AI כותב ממנו סיכום, שאלות תרגול, כרטיסיות ומילון מושגים. התוצאה עוברת בדיקות קבועות, נשמרת בפורמט קבוע ומתפרסמת לסטודנטים.

### התהליכים במערכת

| # | תהליך | טריגר | קלט | שלב ה AI | החלק הדטרמיניסטי | בדיקה קבועה אחרי ה AI | פלט |
|---|---|---|---|---|---|---|---|
| 1 | עיבוד חומר לימוד | קובץ חדש במודל (סנכרון כל 30 דקות), העלאה באתר, או קובץ בתיקייה `inbox/` | PDF או PPTX | כתיבת סיכום, נושאים, שאלות אמריקאיות, כרטיסיות ומושגים לפי סכמת JSON | המרה ל PDF, רינדור שקפים, חילוץ טקסט, זיהוי הקורס לפי מילות מפתח, מספור השיעור | `checkLecture`: 4 אפשרויות שונות לכל שאלה, `correctIndex` חוקי, טווח שקפים חוקי, הסרת כפולים, דחייה של סיכום ריק | `data/lectures/<id>/content.json`, עמוד השיעור באתר, פריט בפיד העדכונים |

| 3 | חילוץ משקלי ציון | סנכרון קובץ הקורסים (כל 12 שעות), ורק כשהטקסט של הסילבוס השתנה (hash) | הסילבוס: דף הסילבוס, PDF במודל או שקפי השיעור הראשון | זיהוי רכיבי הציון, המשקלים, "מגן" וציון מינימום | חישוב ההשוואה ל hash, מחשבון הציונים ("כמה צריך במבחן") | `checkGrading`: משקלים חיוביים, סכום של 100 (אחרת מסומן במחשבון), ציון מינימום בין 0 ל־100 | `grading` בקורס, מחשבון הציונים |
| 4 | תרגול ברמת שיעורי הבית | לחיצה על "צור תרגילים חדשים" בלשונית שיעורי הבית | שיעורי הבית והתרגולים של הקורס | כתיבת תרגילים עם פתרון מלא, ושאלות אמריקאיות | הסרת תרגילים שכבר קיימים | `checkProblems` ו־`checkQuiz` | `data/practice/<course>.json` |
| 5 | שאלות נוספות לשיעור | לחיצה על "צור 6 שאלות חדשות" בלשונית התרגול של שיעור | שקפי השיעור | כתיבת שאלות | הסרת שאלות שכבר קיימות | `checkQuiz` | `extraQuiz` בתוך `content.json` |
| 6 | דוח עומס שבועי | יום ראשון מ־07:00 (נבדק כל שעה), או "הפקה עכשיו" | ההגשות, המבחנים והבחנים, החומר החדש מהשבוע שעבר | כותרת קצרה לשבוע ועצה לכל קורס | כל התאריכים, הספירות ונקודות העומס (`shared/weekly-load.js`) | `checkWeeklyText`: בלי שמות קורסים ומספרים בכותרת, רק קורסים שבדוח, רק תאריכים מהעובדות. מה שנכשל מוחלף בנוסח קבוע | `data/weekly/<תאריך>.json`, עמוד "דוח עומס שבועי", פריט בפיד |

גם הסנכרון עם המודל והפרסום לאתר נרשמים ביומן ההרצות, אבל אין בהם שלב AI.

### איפה ה AI ואיפה הקוד

ה AI פועל רק בקצוות, כשהקלט לא מובנה (טקסט של שקפים וסילבוסים) או כשצריך ניסוח לבני אדם. כל חישוב, תאריך, ספירה והחלטה נעשים בקוד קבוע. אחרי כל שלב AI מופעלת בדיקה קבועה (`server/lib/checks.js`, ולדוח השבועי `server/lib/weekly.js`), עם שלוש רמות:

- **תוקן** – הפלט תוקן לפי כלל, למשל שאלה עם שלוש אפשרויות הוסרה.
- **אזהרה** – הפלט נשמר, אבל כדאי לבדוק אותו, למשל משקלים שלא מסתכמים ל־100.
- **נדחה** – הפלט לא נשמר, למשל סיכום ריק. השיעור מסומן "יצירת הסיכום נכשלה", ואפשר לנסות שוב.

כל ממצא מופיע ביומן ההרצות (סעיף 6).

## 2. מה צריך לפני שמתחילים

- **macOS** (המערכת נבנתה ונבדקה עליו).
- **Node.js 22**: <https://nodejs.org> (גרסת LTS). בדיקה: `node -v`.
- **poppler**, לרינדור שקפים ולחילוץ טקסט: `brew install poppler`. בלי Homebrew, מתקינים אותו מ־<https://brew.sh>.
- **רק לקבצי PPTX:** Microsoft PowerPoint או LibreOffice (`brew install --cask libreoffice`). לקבצי PDF לא צריך.
- **חיבור ל AI**, אחד משני אלה:
  - **מפתח API של Anthropic** (תשלום לפי שימוש, בערך כמה סנטים לשיעור): <https://console.anthropic.com>.
  - **Claude Code מותקן ומחובר**, בתוכנית שכוללת אותו: `npm install -g @anthropic-ai/claude-code`, ואז `claude` ו־`/login`.
- **גישה למאגר הקוד** (המאגר פרטי – צריך לבקש הזמנה מבעל המאגר).

## 3. התקנה

```bash
git clone https://github.com/yoavziv3/study-hub.git
cd study-hub
npm install
```

יוצרים בתיקייה קובץ `.env` עם התוכן הבא. ההגדרות האלה שומרות את כל הנתונים בתיקיית בדיקה נפרדת, ולא שולחות כלום לענן או ל git:

```ini
# AI – אחת משתי האפשרויות:
AI_PROVIDER=api
ANTHROPIC_API_KEY=sk-ant-...        # המפתח שלכם
# AI_PROVIDER=cli                   # או: Claude Code המחובר במחשב
# AI_PROVIDER=gemini                # או: Gemini (מפתח חינמי מ-aistudio.google.com/apikey)
# GEMINI_API_KEY=...

# נתוני בדיקה בתיקייה נפרדת, ויומן ההרצות לידם
STUDY_DATA_DIR=./test-data
STUDY_RUNLOG=./test-data/runs.jsonl

# מודל מדומה במקום המודל של האוניברסיטה
MOODLE_URL=http://localhost:9911/moodle

# בלי ענן, בלי פרסום ל git, בלי התראות ובלי פורטל
AUTO_PUBLISH=0
CLOUD_URL=
STUDY_ADMIN_SECRET=
PUSH_TICK=0
PORTAL_RELAY=0
```

## 4. הרצה מקצה לקצה (הצינור)

### שלב 1: מפעילים את המודל המדומה

בטרמינל אחד. במקום `<קובץ.pdf>` שמים נתיב לכל קובץ PDF של מצגת (המודל המדומה מגיש אותו בתור הקבצים של הקורס):

```bash
node scripts/dev/mock-moodle.mjs 9911 <קובץ.pdf>
```

הפלט הצפוי: `mock moodle on http://localhost:9911/moodle`.

### שלב 2: מפעילים את המערכת

בטרמינל שני, באותה תיקייה:

```bash
npm start
```

הפלט הצפוי: `Study Hub פועל: http://localhost:5180`. פותחים את הכתובת בדפדפן.

### שלב 3: מתחברים למודל המדומה

בתפריט הצד: **סנכרון מודל**. מתחברים עם המשתמש המדומה:

- שם משתמש: `test-all`
- סיסמה: `all-test-pass`

אלה פרטים של משתמש בדיוני, שקיים רק במודל המדומה.

### שלב 4: מה אמור לקרות, בלי לגעת בכלום

1. **תוך כדקה:** הסנכרון הראשון רץ מעצמו, ושני קבצים נקלטים בקורס **מבוא לכלכלה**: "הרצאה 2" ו"תרגול 2". הסילבוס מסונן החוצה בכלל קבוע.
2. **כל קובץ עובר את השלבים** המרה → רינדור → חילוץ טקסט → ניתוח AI → בדיקות → מוכן. את השלבים רואים בעמוד הקורס.
3. **אחרי כמה דקות לכל קובץ:** בעמוד השיעור יש סיכום, נושאים, שאלות, כרטיסיות ומושגים. בפיד **עדכונים** מופיע פריט "הרצאה חדשה".
4. **ב"יומן הרצות"** מופיעות הרצות של "סנכרון מודל", "עיבוד חומר לימוד" ו"כתיבת סיכום מובנה", עם מועד, קלט, פלט, משך, ומה מצאו הבדיקות.

### שלב 5: הרצה שנייה, על קלט אחר

מעתיקים קובץ PDF אחר לתיקייה `inbox/econ/`. התיקייה במעקב, אז הקובץ נקלט מעצמו לקורס מבוא לכלכלה ועובר את אותו צינור. בסוף הוא מועבר ל־`inbox/נקלטו/`. ביומן ההרצות מופיעה הרצה נוספת, עם הטריגר "העלאה".

## 6. יומן ההרצות ובדיקת הפלט

- **העמוד "יומן הרצות"** בתפריט הצד מציג כל הרצה: התהליך, הטריגר, ההתחלה והסיום, המשך, הקלט, הפלט, הסטטוס והממצאים של הבדיקות. לחיצה על הרצה פותחת את הפרטים.
- **"ייצוא ל CSV"** שומר את ההרצות המוצגות לקובץ שנפתח באקסל, בשביל טבלת ההרצות בנספח.
- **הקובץ עצמו** הוא `test-data/runs.jsonl`: שורת JSON לכל הרצה.
- **הסטטוסים:**
  - **תקין** – בלי ממצאים.
  - **תוקן בבדיקות** – היו ממצאים מסוג "תוקן" או "אזהרה", והפלט נשמר.
  - **נדחה בבדיקות** – הפלט לא נשמר.
  - **נכשל** – שגיאה, למשל אין חיבור ל AI.

**בדיקה ידנית של פלט:** בוחרים שאלה בלשונית התרגול ומשווים אותה לשקף שהיא מפנה אליו. בפלט של תהליך 3 בודקים שסכום המשקלים במחשבון זהה לסילבוס.

## 7. תקלות נפוצות

| מה רואים | מה עושים |
|---|---|
| "יצירת הסיכום נכשלה" ביומן, עם השגיאה `Failed to authenticate` | החיבור של Claude Code פג: מריצים `claude` ואז `/login`, ואז "יצירת סיכום מחדש" |
| השגיאה `429` או `usage_limit` | הגעתם למגבלת השימוש. מחכים, ואז "יצירת סיכום מחדש" |
| השגיאה `ANTHROPIC_API_KEY` | המפתח חסר או שגוי ב־`.env` |
| השגיאה `Gemini daily quota` | נוצלה המכסה היומית החינמית של Gemini. היא מתאפסת בחצות לפי שעון קליפורניה, והעיבוד ממשיך לבד |
| קובץ PPTX נתקע בשלב "המרה" | חסר PowerPoint או LibreOffice (סעיף 2) |
| אין שקפים ואין טקסט | חסר poppler: `brew install poppler` |
| הפורט 5180 תפוס | מוסיפים `PORT=5181` ל־`.env` |
| "נדחה בבדיקות" | ה AI החזיר פלט שלא עבר את הבדיקות, למשל סיכום ריק. מריצים שוב, ואם זה חוזר, הפרטים נמצאים בממצאים ביומן |

## 8. ניקוי

עוצרים את שני הטרמינלים (Ctrl+C) ומוחקים את תיקיית הבדיקה:

```bash

```
